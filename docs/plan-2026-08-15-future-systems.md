## 1. 👗 ระบบแฟชั่น

> **ที่เจ้าของเกมสั่งไว้:** เปลี่ยนกราฟิกตัวละครได้จริง · มีให้เลือกหลายแบบแน่น ๆ ในเกม ·
> ต้องออกมาเท่ · **ราคาแพงมาก** · แยกเป็น **ชุดที่ใส่** กับ **อาวุธ** คนละช่อง

### ทำไมง่าย
ตัววาดตัวละครที่ [sprite.js](../license_server/web_static/sprite.js) ซ้อนเลเยอร์อยู่แล้ว —
`RACE_LOOK` (เผ่า) → `ARMOR_LOOK` (เกราะ) → `CLASS_LOOK` (คลาส) → `WEAPON_LOOK` (อาวุธ)

แฟชั่นคือ **การสวมทับเลเยอร์เดิมตอนวาด โดยไม่แตะข้อมูลของจริง**
เกราะเหล็กที่ใส่อยู่ยังเป็นเกราะเหล็ก (ค่าป้องกัน ความคงทน เหมือนเดิมทุกอย่าง)
แค่ **วาดออกมาเป็นชุดอื่น** เท่านั้น

### สองช่อง แยกกันอิสระ
| ช่อง | ทับอะไร | ตัวอย่าง |
|---|---|---|
| 👘 **ชุด** | `ARMOR_LOOK` | ชุดราตรี · ชุดเกราะทองคำ · ชุดนินจา · ชุดมังกร · ชุดผี |
| ⚔️ **อาวุธ** | `WEAPON_LOOK` | ดาบเพลิง · เคียวมรณะ · คทาคริสตัล · ดาบแสง · ค้อนยักษ์ |

ใส่แยกกันได้ (ชุดนินจา + ดาบเพลิง ก็ได้) · ถอดทีละช่องได้ · ไม่ใส่ = เห็นของจริงเหมือนเดิม

### สิ่งที่ต้องทำ
1. คอลัมน์ `fashion` (JSON `{"outfit": "...", "weapon": "..."}`) + `fashion_owned` (JSON list)
   เพิ่มผ่าน `NEW_PLAYER_DEFAULTS` เหมือนคอลัมน์อื่น
2. `FASHION_OUTFIT` / `FASHION_WEAPON` ใน sprite.js — วาดด้วยโค้ดเหมือนสัตว์เลี้ยงกับมอน
   **ไม่ต้องมีไฟล์ภาพเลย** เพิ่มชุดใหม่ = เพิ่มตารางสีกับรูปทรง ไม่ต้องวาดรูป
3. `bot/fashion.py` — ตรรกะกลาง: มีชุดอะไรบ้าง · ซื้อ · ใส่ · ถอด (ดิสกับเว็บเรียกตัวเดียวกัน)
4. หน้าเว็บ: แผง 👗 ตู้เสื้อผ้า — **พรีวิวตัวเองก่อนซื้อ/ก่อนใส่** (สำคัญเพราะแพงมาก)
5. ดิส: `!fashion` โชว์ตู้ + ปุ่มใส่/ถอด

### ราคา — ให้แพงจริงตามที่สั่ง
เกมนี้ Lv100 ล้มมอนได้ทองเฉลี่ย **865,975 ทอง/ตัว** (วัดจากของจริง)
ถ้าอยากให้ชุดหนึ่ง "ต้องตั้งใจเก็บ" จริง ๆ:

| ระดับ | ราคาที่เสนอ | = ล้มมอนกี่ตัว |
|---|---|---|
| ธรรมดา | 50M | ~58 ตัว |
| หายาก | 300M | ~350 ตัว |
| ตำนาน | 2,000M | ~2,300 ตัว |
| ระดับเหรียญ | ซื้อด้วย 🪙 เหรียญ (ข้อ 4) เท่านั้น | — |

**นี่คือที่ทิ้งเงินที่ดีที่สุดในเกม** เพราะแพงเท่าไหร่ก็ไม่กระทบสมดุลการต่อสู้เลยสักนิด
ตรงกับที่เคยสั่งให้เนิฟความรวย — ยิ่งคนรวย ยิ่งมีที่ให้ใช้

### จุดที่ต้องระวัง
- **แฟชั่นห้ามมีผลต่อค่าสถานะเด็ดขาด** ไม่งั้นกลายเป็น pay-to-win
  เขียนเทสบังคับ: ใส่/ถอดแฟชั่นแล้ว **ค่าต่อสู้ทุกตัวต้องเท่าเดิมเป๊ะ**
  (เต๋า · ดาเมจ · ป้องกัน · ความคงทน · HP)
- **ห้ามใส่แฟชั่นแล้วดูเหมือนของที่ยังไม่มี** — เช่นใส่ชุดที่ดูเหมือนเกราะระดับสูงสุด
  แล้วคนอื่นเข้าใจผิดว่าแกร่ง อันนี้ไม่ใช่บั๊กแต่เป็นเรื่องที่ต้องตั้งใจเลือกว่าจะให้เป็นแบบไหน
- ที่มาของชุด: ร้านแฟชั่น (ทองก้อนใหญ่) · กาชาแฟชั่น (แยกตู้จากกาชายศ) · ซีซั่นพาส · อีเวนต์
- ตอนวาดคู่ (ข้อ 2) กับตอนสู้ PVP (ข้อ 3) ต้องเห็นแฟชั่นด้วย
  → **ออกแบบให้ `drawCharacter()` รับ fashion ตั้งแต่แรก** ทุกที่ที่วาดตัวละครจะได้ถูกหมดทีเดียว
  (ที่วาดตัวละครตอนนี้: หน้าโปรไฟล์ · แถบตัวละคร · ฉากผจญภัย · การ์ดใต้ฉาก)

## 3. ⚔️ PVP + กิลด์วอร์ แนว Worms W.M.D

### ประเมินตรง ๆ ก่อน
**นี่คือการสร้างเกมใหม่อีกเกมในเกม** ไม่ใช่การต่อยอดของเดิม

ของที่มีตอนนี้:
- [pvp_duel.py](../bot/cogs/pvp_duel.py) 168 บรรทัด — ดวลผลัดกันทอยเต๋าในดิส
- [guild_war.py](../bot/cogs/guild_war.py) 349 บรรทัด — สงครามกิลด์แบบสะสมแต้ม

ของที่ต้องสร้างใหม่เกือบทั้งหมด: ระบบห้อง · คิวจับคู่ · ลำดับเทิร์น · นาฬิกาต่อเทิร์น ·
วิถีกระสุน · แผนที่ที่พังได้ · ระบบภัยพิบัติ · การซิงก์สถานะหลายคน · UI ควบคุมบนมือถือ

### ตัดสินใจสำคัญ 3 ข้อ

**ก. เว็บเท่านั้น — ดิสทำไม่ได้**
เกมแบบนี้ต้องวาดทุกเฟรมและกดปุ่มตอบสนองทันที ดิสส่งได้แค่ข้อความกับปุ่ม
ดิสจะเหลือหน้าที่ "ตั้งวง/ประกาศผล" เท่านั้น

**ข. ไม่ต้องใช้ WebSocket**
เกมผลัดเทิร์นไม่ใช่เกมเรียลไทม์ — ถามเซิร์ฟเวอร์ทุก 1 วินาทีก็พอ
ประหยัดงานมหาศาลเทียบกับการวางระบบ socket ใหม่ทั้งชุด
(ถ้าวันหนึ่งรู้สึกหน่วงค่อยเปลี่ยน ตอนนั้นค่อยคุ้มที่จะลงแรง)

**ค. เซิร์ฟเวอร์เป็นเจ้าของทุกอย่าง (กติกาเหล็กของโปรเจ็คนี้)**
ตำแหน่ง · เลือด · แผนที่ที่พังไปแล้ว · ผลกระสุน — คำนวณที่เซิร์ฟเวอร์ทั้งหมด
เบราว์เซอร์แค่วาดตามกับส่ง "ฉันยิงมุมนี้ แรงเท่านี้" ไปให้
ไม่งั้นเปิด devtools โกงได้ทันที (บทเรียนเดียวกับ NPC ปลอมตัวที่เพิ่งแก้ไป)

### แผนที่ที่พังได้ — ทำยังไงให้ไม่หนัก
- แผนที่เป็น **บิตแมสก์ขาวดำ** เช่น 160×80 = 12,800 บิต = 1.6KB
- ยิงโดน → เจาะรูวงกลมในมาสก์ → ส่งเฉพาะ **ส่วนที่เปลี่ยน** กลับไป ไม่ต้องส่งทั้งแผนที่
- พื้นหลังใช้สีของ 9 ทวีปที่มีอยู่แล้วใน [scene.js](../license_server/web_static/scene.js) `MAPS`

### เฟสที่แนะนำ (อย่าทำรวดเดียว)
| เฟส | ได้อะไร | ทดสอบได้ว่า |
|---|---|---|
| A | ห้อง + คิว + ลำดับเทิร์น + นาฬิกา (ยังไม่มีแผนที่) | 2 คนผลัดกันกดปุ่มได้จริง ไม่ค้าง |
| B | แผนที่ + เดิน + ยิงโค้ง + แผนที่พัง | ยิงแล้วแผนที่เป็นรู เห็นตรงกันทั้งสองฝั่ง |
| C | ไอเทม/สกิลตามคลาส + เอฟเฟกต์ + เสียง | สกิลทั้ง 4 คลาสใช้ได้ในสนาม |
| D | ภัยพิบัติตอนใกล้หมดเวลา + เงื่อนไขชนะ | เกมจบได้เสมอ ไม่มีตาที่ค้างชั่วนิรันดร์ |
| E | ต่อกับกิลด์วอร์ + รางวัล + อันดับ | กิลด์ประกาศศึกแล้วเข้าสนามได้ |

**เฟส A คือตัวตัดสิน** — ถ้าเฟส A ผ่านสวย ที่เหลือคือการต่อเติม
ถ้าเฟส A ยุ่งยากกว่าที่คิด ให้หยุดคิดใหม่ก่อนลงแรงเฟส B-E

### จุดที่จะเจ็บแน่ ๆ
- **คนหลุดกลางเกม** — ต้องมีนาฬิกาบังคับข้ามเทิร์น ไม่งั้นทั้งห้องค้าง
  (บทเรียนเดียวกับ `expire_pending` ที่เพิ่งแก้ไปเรื่องไฟต์หมดอายุ)
- **มือถือ** — ต้องเล็งด้วยนิ้วได้จริง ออกแบบ UI ควบคุมก่อนเขียนเอนจิน ไม่ใช่ทีหลัง
- **สมดุล** — คนเลเวลสูงเจอเลเวลต่ำ ต้องมีการจัดกลุ่มหรือปรับค่าให้เท่ากันในสนาม

## 4. 🪙 เหรียญคริปโต / NFT

### ⚠️ ต้องตัดสินใจก่อนเขียนโค้ดบรรทัดแรก

**คำว่า "คริปโต" มีสองความหมายที่ต่างกันคนละโลก:**

**แบบ ก. เหรียญในเกมล้วน ๆ (แนะนำ)**
เป็นแค่สกุลเงินที่สองในเกม ไม่ได้อยู่บนบล็อกเชน แลกเป็นเงินจริงไม่ได้
→ **ทำได้เลย ไม่มีปัญหาอะไร** เป็นแค่ระบบเกมธรรมดา
→ ได้คุณค่าทางเกมครบ: เป็นเป้าหมายปลายทางของคน Lv100 ที่ EXP ล้นแล้วไม่มีที่ใช้

**แบบ ข. คริปโต/NFT จริงบนบล็อกเชน ที่ขายเป็นเงินได้**
→ **เรื่องนี้เกินขอบเขตงานเขียนโค้ด** ในไทยการออกโทเคนดิจิทัลให้คนซื้อ/แลกเป็นเงินได้
อยู่ใต้ พ.ร.ก. สินทรัพย์ดิจิทัลฯ และการกำกับของ ก.ล.ต.
→ เกมนี้**ขายทองด้วยเงินจริงอยู่แล้ว** (`!payment` / หน้าเติมเกม)
ถ้าเปิดทางให้ เงินจริง → ทอง → เหรียญ → เงินจริง มันคือเส้นทางแลกเงินสองทาง
ซึ่งเป็นจุดที่ทั้งกฎหมายและการฟอกเงินเข้ามาเกี่ยว
→ **ถ้าจะเอาแบบนี้จริง ต้องปรึกษาทนาย/ผู้เชี่ยวชาญก่อน ไม่ใช่เริ่มที่โค้ด**

**คำแนะนำ: ทำแบบ ก. ก่อน** มันได้ความสนุกเกือบทั้งหมดโดยไม่มีความเสี่ยงเลย
ถ้าวันหนึ่งอยากไปแบบ ข. โครงสร้างแบบ ก. ก็ยังต่อยอดได้ ไม่เสียของ

### เศรษฐศาสตร์ — วัดจากตัวเลขจริงในเกมแล้ว

ที่ Lv100 ล้มมอน 1 ตัวได้เฉลี่ย **EXP 290 · ทอง 865,975**

สูตรที่เสนอมา (EXP ส่วนเกิน 1,000,000 + ทองคำแท่ง 1000M = 1 เหรียญ):

| | จำนวน |
|---|---|
| ต้องล้มมอน | ~3,448 ตัว |
| เดินเร็วราว | ~8,000 ก้าว |
| ทองที่ได้ระหว่างนั้น | ~2,986M = **2.99 แท่ง** |

**ข้อค้นพบสำคัญ: เงื่อนไขทองแทบไม่ได้กั้นอะไรเลย**
ระหว่างเก็บ EXP ให้ครบ ทองมาเองเกือบ 3 เท่าของที่ต้องใช้
→ ตัวจำกัดจริงคือ EXP อย่างเดียว ทองเป็นแค่พิธีกรรม

**ทางเลือก:**
- อยากให้ทองมีความหมายจริง → ขึ้นเป็น 3-5 แท่ง/เหรียญ
- หรือตัดเงื่อนไขทองทิ้ง ใช้ EXP อย่างเดียว (ตรงไปตรงมากว่า อธิบายง่ายกว่า)
- **ข้อดีที่ควรเก็บไว้: มันเป็นที่ทิ้งทองที่ใหญ่ที่สุดในเกม** ตรงกับที่เคยสั่งให้เนิฟความรวย

### สิ่งที่ต้องทำ (แบบ ก.)
1. คอลัมน์ `overflow_exp` — Lv100 แล้ว EXP ที่เกินไม่ทิ้ง เก็บสะสมแทน
   **จุดแก้: [adventure_core.py](../bot/adventure_core.py) ตรง `if current_level >= 100: current_exp = 0`**
   (ตรงนี้ทิ้ง EXP ทั้งหมดอยู่ตอนนี้)
2. คอลัมน์ `coins` + `bot/crypto.py` (ตรรกะกลาง ดิส+เว็บใช้ร่วม)
3. หน้าแลก: EXP ส่วนเกิน + ทองแท่ง → เหรียญ (ทำใน transaction เดียว แบบเดียวกับ `market.py`)
4. ที่ใช้เหรียญ: แฟชั่นระดับตำนาน · ช่องอาร์ติแฟกต์พิเศษ · ยศประจำตัว · ตราในตลาดผู้เล่น
   **สำคัญ: ห้ามให้ซื้อของที่มีผลต่อค่าต่อสู้** ไม่งั้นกลายเป็น pay-to-win ผ่านทางอ้อม
5. ตาราง `coin_log` — ทุกการได้/ใช้เหรียญต้องมีประวัติ (ถ้าวันหนึ่งไปแบบ ข. จะขาดไม่ได้)

## คำถามที่ต้องตอบก่อนเริ่มแต่ละข้อ

**แฟชั่น** — เคาะแล้ว: 2 ช่อง (ชุด/อาวุธ) · แพงมาก · เท่ ✅
เหลือ: จะมีกี่แบบตอนเปิด? (แนะนำเริ่ม 8 ชุด + 8 อาวุธ แล้วค่อยเติมเรื่อย ๆ)
ชุดระดับตำนานซื้อด้วยทองได้ไหม หรือต้องใช้เหรียญ (ข้อ 4) เท่านั้น?

**ครอบครัว** — ลูกได้ประโยชน์อะไร? (ถ้าไม่มีเลยจะไม่มีใครใช้ ถ้ามีเยอะไปจะกลายเป็นบังคับหาคู่)

**PVP** — กี่คนต่อห้อง? (2 คนง่ายสุด · 4-8 คนสนุกกว่าแต่ยากกว่ามาก)
เทิร์นละกี่วินาที? แพ้แล้วเสียอะไรไหม หรือเล่นสนุกล้วน?

**เหรียญ** — **แบบ ก. หรือ ข.?** (ต้องตอบข้อนี้ก่อนเขียนโค้ดบรรทัดแรก)
เหรียญเอาไปซื้ออะไรได้บ้าง?

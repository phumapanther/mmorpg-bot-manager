# ⚔️ หมวด PVP — ห้องเล่นกับเพื่อน + ระบบเพื่อน

> เขียน 2026-08-17 · ต่อยอดจากหัวข้อ 4 ใน [แผนระบบใหม่ 5 ชุด](plan-2026-08-15-future-systems.md)
> สถานะ: **ชั้น ① ระบบเพื่อนเสร็จแล้ว** (commit ถัดจาก 0c565d8) · เทส 1505 ผ่าน
> มินิเกมที่เจ้าของเกมเคาะให้เปิดตัว: 🪱 สนามรบผลัดเทิร์น · 🎲 แข่งเต๋าบันไดงู · ⚔️ ดวลมอนอัตโนมัติ

เจ้าของเกมสั่งเพิ่ม: หมวด PVP ที่**สร้างห้องเล่นกับเพื่อนได้** มีมินิเกมหลายตัว
เล่นกับบอทก็ได้ · แต่ละโหมดจำกัดคนไม่เท่ากันและแบ่งฝ่ายไม่เหมือนกัน (เดี่ยว/ทีม)
ชวนเพื่อนเข้าล็อบบี้ → กดพร้อม → เริ่มเกม
ระบบเพื่อน: **คัดลอกไอดี Discord มาวางแล้วกดเพิ่ม** · ดูโปรไฟล์เพื่อนได้

## ภาพรวม 3 ชั้น

```
① 👥 ระบบเพื่อน        ← ไม่ผูกกับเกมไหนเลย ใช้ได้ทั้งเว็บ ทำก่อน
      เพิ่มด้วยไอดี Discord · ดูโปรไฟล์ · ลบ

② 🚪 ล็อบบี้ (โครงกลาง)  ← ไม่รู้จักกติกาเกมสักตัว
      สร้างห้อง · เลือกโหมด · ชวนเพื่อน · จัดทีม · กดพร้อม · เริ่ม

③ 🎮 มินิเกม             ← เสียบเข้าโครงข้างบน เพิ่มทีละตัวได้เรื่อย ๆ
      แต่ละตัวประกาศ: จำนวนคน · เดี่ยว/ทีม · ซ้อมกับบอทได้ไหม
```

**เหตุผลที่แบ่งแบบนี้:** ชั้น ① กับ ② เขียนครั้งเดียวใช้ได้กับทุกมินิเกมตลอดไป
เพิ่มเกมใหม่ = เพิ่มแถวในตารางโหมด + โมดูลเกมหนึ่งไฟล์ ไม่ต้องแตะล็อบบี้อีกเลย
(โครงเดียวกับหมวดคาสิโนที่เพิ่มเกมได้โดยไม่รื้อของเดิม)

## ① 👥 ระบบเพื่อน — ✅ เสร็จแล้ว 2026-08-17

### เพิ่มเพื่อนยังไง
ไอดี Discord **คือ** `user_id` ในตาราง `players` อยู่แล้ว — วางไอดีแล้วเช็คว่ามีในเกมไหม จบ
ไม่ต้องมีระบบค้นหาชื่อ ไม่ต้องมีรหัสเชิญ

```
วางไอดี → มีในตาราง players ไหม
   ไม่มี  → "❌ ไอดีนี้ยังไม่เคยเล่นเกมนี้"
   ตัวเอง → "❌ เพิ่มตัวเองไม่ได้"
   มีแล้ว → "❌ เป็นเพื่อนกันอยู่แล้ว"
   ผ่าน   → เพิ่มเลย
```

### ตัดสินใจ: เพิ่มแล้วเป็นเพื่อนทันที ไม่ต้องรออนุมัติ
เพราะการเป็นเพื่อนในเกมนี้ทำได้แค่ "ชวนเข้าล็อบบี้" กับ "ดูโปรไฟล์" ซึ่งไม่มีอันตราย
ระบบขอ-อนุมัติทำให้โค้ดเพิ่มเท่าตัวและต้องมีหน้าแจ้งเตือนอีกชุด
**เก็บไว้เผื่อ:** ถ้ามีคนกวน ค่อยเพิ่มปุ่มบล็อกทีเดียว ถูกกว่าทำระบบอนุมัติมาก

เพิ่มทีเดียวเป็นเพื่อนกันทั้งสองฝั่ง (เขียน 2 แถว) ไม่งั้นฝั่งหนึ่งชวนได้ อีกฝั่งชวนไม่ได้

### ตาราง
```sql
CREATE TABLE friends (
    user_id   INTEGER NOT NULL,
    friend_id INTEGER NOT NULL,
    since     INTEGER NOT NULL,
    PRIMARY KEY (user_id, friend_id)
);
```
อยู่ใน `game_data.db` (ที่เดียวกับ `players`) เพราะต้อง JOIN กับโปรไฟล์ตลอด
โครงเดียวกับตาราง `partners` ที่มีอยู่แล้ว

### โปรไฟล์เพื่อน — โชว์อะไร
เอา `profile_embed` ที่มีอยู่แล้วมาแปลงเป็น JSON: ชื่อ · เลเวล · เผ่า/คลาส · ยศ ·
สัตว์เลี้ยง · แฟชั่นที่ใส่ (วาดตัวละครให้ดูได้เลย ใช้ `drawCharacter` ตัวเดิม) ·
คู่สมรส · กิลด์ · ออนไลน์ล่าสุด
**ไม่โชว์**: ทอง · ของในกระเป๋า · ธนาคาร — ไม่ใช่เรื่องของคนอื่น

### ไฟล์
| ไฟล์ | ทำอะไร | สถานะ |
|---|---|---|
| `bot/friends.py` | ตรรกะกลาง: `add` · `remove` · `list_of` · `profile_of` | ✅ |
| `license_server/web_api.py` | `GET/POST /me/friends` · `GET /friends/{id}/profile` | ✅ |
| `play.html` + `play.js` | แผง 👥 เพื่อน + หน้าโปรไฟล์เพื่อน | ✅ |
| `tests/test_friends.py` | 32 เทส เน้นความเป็นส่วนตัวกับการกันปั๊มตัวละคร | ✅ |

**บทเรียนที่เจอตอนทำ:** `get_player()` **สร้างตัวละครใหม่ให้ทันที**ถ้ายังไม่มี
ถ้าเอามาใช้เช็คว่า "ไอดีนี้มีในเกมไหม" การวางไอดีมั่ว ๆ จะกลายเป็นปั๊มตัวละครเปล่าเข้าฐานข้อมูล
จึงต้องมี `friends.exists()` ที่ query ตรง ๆ (มีเทสคุมไว้แล้ว)

**บทเรียนอีกข้อ:** `"๑๒๓๔๕".isdigit()` เป็น `True` และ `int()` แปลงได้จริงใน Python
ตัวตรวจไอดีจึงต้องเช็ค `isascii()` ด้วย

## ② 🚪 ล็อบบี้ — โครงกลางที่ไม่รู้จักกติกาเกมสักตัว

### ตารางโหมด (เพิ่มเกมใหม่ = เพิ่มแถวเดียว)
```python
MODES = {
  "worms_solo": {"name": "🪱 สนามรบผลัดเทิร์น (เดี่ยว)",
                 "min": 2, "max": 4, "teams": 0, "bot": True},
  "worms_team": {"name": "🪱 สนามรบผลัดเทิร์น (ทีม)",
                 "min": 4, "max": 8, "teams": 2, "bot": True},
  ...
}
```
`teams: 0` = ตัวใครตัวมัน · `teams: 2` = แบ่งสองฝ่าย (เว็บโชว์ปุ่มสลับฝ่าย)

### วงจรชีวิตห้อง
```
สร้าง → waiting ──(ครบขั้นต่ำ + พร้อมทุกคน + หัวห้องกดเริ่ม)──→ running → done
          │                                                        │
          └──(ว่างเกิน 10 นาที / คนออกหมด)──→ ล้างทิ้ง ←───────────┘
```

### ตาราง (อยู่ใน `web.db` — บอทไม่เกี่ยวกับล็อบบี้เลย)
```sql
CREATE TABLE lobbies (
    id TEXT PRIMARY KEY,           -- รหัสห้องสั้น ๆ พิมพ์ต่อกันได้
    mode TEXT NOT NULL,
    host_id TEXT NOT NULL,
    status TEXT DEFAULT 'waiting', -- waiting | running | done
    created_at REAL, touched_at REAL
);
CREATE TABLE lobby_members (
    lobby_id TEXT, user_id TEXT, team INTEGER DEFAULT 0,
    ready INTEGER DEFAULT 0, joined_at REAL,
    PRIMARY KEY (lobby_id, user_id)
);
CREATE TABLE lobby_invites (
    lobby_id TEXT, to_user TEXT, from_user TEXT, at REAL,
    PRIMARY KEY (lobby_id, to_user)
);
```

### ตัดสินใจทางเทคนิค
**ก. ไม่ใช้ WebSocket** — ถามเซิร์ฟเวอร์ทุก 1.5 วิ พอสำหรับหน้ารอ
(เกมผลัดเทิร์นก็ไม่ต้องถี่กว่านี้ ตามที่เคยเคาะไว้ในแผนเดิม)

**ข. ห้องค้างต้องหายเอง** — บทเรียนเดียวกับ `expire_pending` ในระบบผจญภัย
ห้องที่ไม่มีใครแตะเกิน 10 นาที = ล้างทิ้งอัตโนมัติ ไม่งั้นตารางจะบวมด้วยห้องผี

**ค. หัวห้องหลุด** — ยกให้คนที่เข้ามาก่อนคนถัดไปทันที ไม่ใช่ปล่อยห้องค้าง

**ง. เซิร์ฟเวอร์เป็นเจ้าของทุกอย่าง** (กติกาเหล็กของโปรเจ็ค)
"พร้อมหรือยัง · อยู่ทีมไหน · เริ่มได้ไหม" ตัดสินที่เซิร์ฟเวอร์เสมอ
เบราว์เซอร์แค่วาดกับส่งปุ่มที่กด

## ③ 🎮 มินิเกม — ยังไม่เคาะว่าจะเปิดตัวด้วยเกมอะไรบ้าง

**กติกาที่มินิเกมทุกตัวต้องทำตาม**
1. ประกาศ `min / max / teams / bot` ให้ล็อบบี้อ่าน
2. รับ "รายชื่อผู้เล่นพร้อมทีม" เข้าไป แล้วคืน "ผลแพ้ชนะ" ออกมา — ไม่ต้องรู้จักเรื่องเพื่อนหรือห้อง
3. **มีโหมดซ้อมกับบอทเสมอ** ทำก่อนโหมดคนจริงทุกครั้ง (เทสคนเดียวได้ งานเดินเร็วกว่ามาก)
4. ตรรกะอยู่ที่เซิร์ฟเวอร์ เบราว์เซอร์ไม่มีกติกา

**ตัวเลือกที่ใช้ของเดิมในเกมได้เยอะ** (ยังไม่เคาะ)

| เกม | คน | ทีม | ใช้ของเดิม | งาน |
|---|---|---|---|---|
| 🪱 สนามรบผลัดเทิร์น | 2-8 | ได้ | ฉากพิกเซล · สีทวีป · สกิลคลาส | **ใหญ่มาก** |
| 🎲 แข่งเต๋าบันไดงู | 2-6 | ได้ | `dice_board` ทั้งชุด | เล็ก |
| 🃏 แบล็คแจ็ควงใหญ่ | 2-5 | ไม่ | `blackjack_core` ทั้งชุด | เล็ก |
| 🧠 ตอบคำถามสัตว์ประหลาด | 2-8 | ได้ | `bestiary` + ข้อมูลมอนจริง | เล็ก-กลาง |
| ⚔️ ดวลมอนอัตโนมัติ | 2-8 | ได้ | เอนจินต่อสู้ทั้งชุด | กลาง |
| 🏃 แข่งวิ่งเก็บของ | 2-6 | ได้ | ฉากพิกเซล · ภาพเหตุการณ์ | กลาง |

**ข้อเสนอ:** เปิดตัวด้วยเกมเล็ก 1-2 ตัวก่อน เพื่อ**พิสูจน์ว่าล็อบบี้ใช้งานได้จริง**
แล้วค่อยลงแรงกับสนามรบผลัดเทิร์นซึ่งเป็นงานใหญ่ที่สุด
(ถ้าเริ่มที่เกมใหญ่เลย ล็อบบี้พังปนกับเอนจินพัง แยกไม่ออกว่าอะไรเสีย)

## จุดที่จะเจ็บแน่ ๆ
- **คนหลุดกลางล็อบบี้** — ต้องมีเวลาหมดอายุ ไม่งั้นทั้งห้องรอคนที่ปิดจอไปแล้ว
- **มือถือ** — หน้าห้องรอต้องอ่านง่ายบนจอแคบ ออกแบบก่อนเขียน
- **สมดุลเลเวล** — เลเวล 100 เจอเลเวล 10 ในมินิเกมที่ใช้ค่าสถานะ ต้องปรับให้เท่ากันในสนาม
- **กันปั๊มรางวัล** — ถ้ามินิเกมให้รางวัล ต้องกันสองคนผลัดกันแพ้-ชนะฟาร์มรางวัล
  (นับรางวัลต่อวัน หรือให้เฉพาะเมื่อผู้เล่นไม่ซ้ำหน้า)

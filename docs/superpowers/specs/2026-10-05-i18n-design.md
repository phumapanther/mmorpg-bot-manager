# ระบบแปลภาษา 4 ภาษา — บอทดิสคอร์ด + เว็บเกม

**วันที่**: 2026-10-05
**สถานะ**: เจ้าของเกมเคาะแนวทางแล้ว รอตรวจสเปก

---

## เป้าหมาย

เกมเล่นได้ 4 ภาษา: **ไทย · อังกฤษ · จีน (ตัวย่อ) · ญี่ปุ่น**

- **บอทดิสคอร์ด** — ตอบตามภาษาที่ผู้เล่นแต่ละคนตั้งในดิสคอร์ด
- **เว็บเกม** — มีปุ่มเลือกภาษาบนแถบเมนู

## การตัดสินใจที่เจ้าของเกมเคาะแล้ว

| # | เรื่อง | เลือก |
|---|---|---|
| 1 | บอทรู้ภาษาผู้เล่นยังไง | **จำจากการกดปุ่ม** แล้วใช้กับคำสั่ง `!` ด้วย (ไม่มี `!lang`) |
| 2 | คำแปลมาจากไหน | **Claude แปลครบ 3 ภาษาตอนทำ** เก็บเป็น JSON แก้เองได้ |
| 3 | แปลอะไรบ้าง | ข้อความระบบ + **ชื่อในเกม** (มอน · ไอเทม · สกิล · ทวีป) |
| 4 | ข้อความที่แอดมินพิมพ์ใน Panel | **ไม่แปล** — แสดงตามที่พิมพ์ |
| 5 | วิธีเขียนในโค้ด | **แนวทาง ก.** — ข้อความไทยเป็นคีย์ + ภาษาปัจจุบันอยู่ใน `contextvars` |
| 6 | ภาษาบอทกับเว็บ | **แยกกัน** — บอทตามดิสคอร์ด · เว็บตามปุ่มที่เลือก |

### ทำไมบอทอ่านภาษาดิสคอร์ดตรง ๆ ทุกครั้งไม่ได้

ดิสคอร์ดส่ง `interaction.locale` มา**เฉพาะตอนกดปุ่ม/เมนู/slash command**
ข้อความที่พิมพ์ (`!bag`) **ไม่มีภาษาของคนพิมพ์ติดมา** — เป็นข้อจำกัดของ API ดิสคอร์ด
บอทใช้ `!` ทั้งหมด 97 คำสั่ง แต่มีปุ่ม/เมนู 208 จุด → คนส่วนใหญ่กดปุ่มตั้งแต่แรก ๆ อยู่แล้ว

## 1. หัวใจ: `bot/i18n.py`

```python
from bot.i18n import tr

await ctx.send(tr("ได้รับ {gold} ทอง", gold=g))
```

> **ชื่อฟังก์ชันคือ `tr` ทั้ง Python และ JS** (แก้ 2026-10-05 ตอนเขียนแผนก้อน 1)
> เดิมสเปกใช้ `tr()` / `t()` แต่โค้ดเดิมใช้ `_` เป็นตัวแปรทิ้ง 53 จุด (`for _ in ...`)
> และ `t` เป็นตัวแปร local ใน JS 26 จุด (`const t = await ...`) — ห่อข้อความในสโคปพวกนั้น
> แล้วจะพังเป็น "not a function" · `tr` ยังไม่มีใครใช้เลย

- `tr(ข้อความไทย, **ตัวแปร)` → คืนคำแปลของภาษาปัจจุบันแล้วเติม `{ตัวแปร}` · **หาไม่เจอ = คืนภาษาไทยเดิม** (ไม่มีวันพัง)
- ภาษาปัจจุบันอยู่ใน `contextvars.ContextVar("lang", default="th")`
- `use_lang(code)` — context manager สำหรับจุดที่ต้องสลับภาษาชั่วคราว (ประกาศลงห้อง)
- `normalize(locale)` — แปลงรหัสดิสคอร์ด/เบราว์เซอร์ → 4 ภาษา:
  `th` → th · `en-US`/`en-GB` → en · `zh-CN`/`zh-TW` → zh · `ja` → ja · **อื่น ๆ → en**
- ข้อความที่มีตัวแปร **ต้องใช้ `{ชื่อ}` แล้วส่งค่าเข้า `tr()`** ไม่ใช่ f-string
  (f-string ประกอบประโยคก่อนแปล → หาคีย์ไม่เจอ) · ลำดับคำแต่ละภาษาไม่เหมือนกัน
  ห้ามต่อประโยคเป็นท่อน ๆ เช่น `tr("ได้รับ") + " 5 " + tr("ทอง")`
- `tr()` รับ**ข้อความตรง ๆ เท่านั้น** ห้ามส่งตัวแปร (`tr(label)`) — สคริปต์ดึงข้อความมองไม่เห็น

### ไฟล์คำแปล

`license_server/web_static/locales/{en,zh,ja}.json` — **ที่เดียว ใช้ร่วมทั้ง Python และ JS**
(อยู่ใต้ `web_static` เพราะเว็บ mount ไว้ที่ `/` แล้ว → JS ดึง `/locales/en.json` ได้เลย)

exe ลูกค้า (`build.spec` · `build_nuitka.py`) ไม่มี `license_server/` → ต้องใส่โฟลเดอร์ `locales`
เป็น data dir ให้ตรง ๆ (แค่ JSON ไม่ใช่โค้ดฝั่งผู้ขาย) · หาไม่เจอเมื่อไหร่ `tr()` ตกเป็นไทยเอง

```json
{ "ได้รับ {gold} ทอง": "Received {gold} gold" }
```

ไม่มี `th.json` — ภาษาไทยคือคีย์เอง

### สคริปต์ดึงข้อความ `scripts/i18n_extract.py`

- สแกน `tr("...")` ใน `.py`/`.js`/`<script>` ในหน้า และป้าย `data-i18n*` ใน `.html` → รายการคีย์ทั้งหมด
- จับ**ข้อความไทยในหน้า HTML ที่ยังไม่ได้ติดป้าย** · **`tr()` ที่รับตัวแปร**
- รายงาน **คีย์ที่ยังไม่มีคำแปล** ในแต่ละภาษา · **คีย์ร้างที่ไม่มีใครใช้แล้ว**
- `--write` เติมคีย์ใหม่ลงทั้ง 3 ไฟล์ (ค่าว่าง) ให้แปลต่อ

### เทสกันพัง `tests/test_i18n.py`

- ทุกคีย์ในโค้ด **มีคำแปลครบ 3 ภาษา** (กันแก้ข้อความไทยแล้วคำแปลหลุดเงียบ)
- `{ตัวแปร}` ในคำแปล **ตรงกับในคีย์ทุกตัว** (กัน `KeyError` ตอน `.format()`)
- `normalize()` ครบทุกกรณีข้างบน

## 2. บอทดิสคอร์ด — ตั้งภาษาให้ถูกที่

### ลำดับการเลือกภาษา

```
players.lang (จำจากการกดปุ่มล่าสุด)
  → ไม่มี: guild.preferred_locale (ภาษาเซิร์ฟเวอร์)
    → ไม่มี: th
```

### จุดตั้งภาษา 2 จุด

**ก. คำสั่ง `!`** — ใน `global_before_invoke` ที่มีอยู่แล้ว ([main.py](../../../bot/main.py))
ตั้ง contextvar ตามลำดับข้างบน · `on_command_error` ได้ภาษาเดียวกันเพราะ
`asyncio.create_task` คัดลอก context ไปด้วย

**ข. ปุ่ม/เมนู** — ⚠️ ใช้ `on_interaction` **ไม่ได้** เพราะดิสคอร์ด.py รัน listener
กับ callback ของปุ่ม**คนละ task** → contextvar ที่ตั้งใน listener ไปไม่ถึง callback

ทางที่ใช้: **คลาสฐาน `bot/views/base.py: LangView(discord.ui.View)`**
- `interaction_check` รันใน task เดียวกับ callback → ตั้ง contextvar ที่นี่ได้
- ทำ 2 อย่าง: ตั้งภาษา = `normalize(interaction.locale)` · บันทึกลง `players.lang`
  **เฉพาะเมื่อเปลี่ยน** (แคชในหน่วยความจำ ไม่เขียน DB ทุกคลิก)
- View ทั้ง 49 ตัวเปลี่ยนไปสืบจาก `LangView` · ตัวที่ override `interaction_check`
  เอง (~15 ตัว) ต้องเรียก `await super().interaction_check(i)` ก่อน
- เทส: grep ว่า**ไม่มีคลาสไหนสืบจาก `discord.ui.View` ตรง ๆ** ยกเว้น `LangView`
  และทุก override เรียก `super()` (กันคนเพิ่ม View ใหม่แล้วลืม)

### คอลัมน์ใหม่

`players.lang TEXT DEFAULT ''` — เพิ่มใน `NEW_PLAYER_DEFAULTS` ระบบ migration เดิมเติมให้เอง

### ประกาศลงห้อง (คนอ่านหลายคน)

อีเวนต์โลก · ประกาศบอส · ลูปเบื้องหลัง → ใช้ **ภาษาเซิร์ฟเวอร์**
ห่อด้วย `with use_lang(normalize(guild.preferred_locale)):`

## 3. เว็บ

### เลือกภาษา

- ปุ่มเลือกภาษาบนแถบเมนู (`#navbar`) — 🇹🇭 ไทย · 🇬🇧 English · 🇨🇳 中文 · 🇯🇵 日本語
- เก็บใน **คุกกี้ `lang`** (ทั้ง JS และเซิร์ฟเวอร์อ่านได้) · ครั้งแรกเดาจาก `navigator.language`
- เปลี่ยนภาษา = ตั้งคุกกี้แล้วรีโหลดหน้า (ง่ายสุด ไม่ต้องไล่อัปเดตทุกจุดบนจอ)

### ข้อความจากเซิร์ฟเวอร์

middleware ใน [api.py](../../../license_server/api.py) อ่านคุกกี้ `lang` → ตั้ง contextvar
→ แกนเกม (`adventure_core` · `market` · คาสิโน · ปาร์ตี้) ที่ห่อ `tr()` ไว้แล้ว
ตอบภาษานั้นเองโดย**ไม่ต้องแก้ signature ฟังก์ชัน**
รวม `HTTPException(detail=...)` ที่เป็นไทยทั้งหมดด้วย

เทส: ยิง endpoint จริงพร้อมคุกกี้ `lang=en` → ข้อความต้องเป็นอังกฤษ
(ยืนยันว่า contextvar ไหลจาก middleware ถึง endpoint ทั้งแบบ `async def` และ `def`)

### ข้อความใน JS

`web_static/i18n.js` — โหลด**ก่อน web.js ทุกหน้า** · `tr("ข้อความไทย", {ตัวแปร})` ทำงานแบบเดียวกับฝั่ง Python

- ดึง `/locales/<lang>.json` แบบ **XHR sync** ให้ `tr()` พร้อมก่อน web.js/play.js รัน
  (บล็อกหน้าเท่า `<script src>` ธรรมดา · ภาษาไทยไม่ดึงอะไรเลย)
- ข้อความใน HTML — ป้ายติดบนแท็ก ข้อความไทยในหน้าคือคีย์ (ไม่ต้องพิมพ์ซ้ำ):

| ป้าย | ใช้กับ | แปล |
|---|---|---|
| `<p data-i18n>ข้อความล้วน</p>` | ข้อความไม่มีแท็กข้างใน | `textContent` |
| `<p data-i18n-html>โอน <b id="x"></b> บาท</p>` | ประโยคเดียวที่มีแท็กข้างใน | `innerHTML` (คำแปลต้องมีแท็ก/id ครบ) |
| `<input placeholder="..." data-i18n-attr="placeholder,title">` | แอตทริบิวต์ | ค่าแอตทริบิวต์ |

- ตั้ง `<html lang>` ตามภาษา → CSS เลือกฟอนต์จีน/ญี่ปุ่นของเครื่อง (`Prompt` ไม่มีอักษร CJK)

## 4. ชื่อในเกม

| ของ | ตอนนี้ | ต้องทำ |
|---|---|---|
| ไอเทม | รหัสตัวเลข · ชื่ออยู่ใน `config.json` | ห่อ `tr()` ตอนแสดงผล |
| ทวีป · สถานะ · แรงก์มอน | คีย์อังกฤษ · ป้ายไทยใน `game_data.py` | ห่อ `tr()` ตอนแสดงผล |
| **มอน** | ⚠️ ชื่อไทย**ต่อท้ายธาตุ**แล้วเก็บลง `adventure_pending` | **แยกเก็บ** `base_name` + `element` · ประกอบตอนแสดงผล |
| สกิล | ป้ายไทยในโค้ด | ห่อ `tr()` ตอนแสดงผล |

**ไฟต์ที่ค้างอยู่ตอนอัปเดต** — แถวเก่ามีแค่ `name` ที่ประกอบแล้ว → แสดงตามเดิม (ภาษาไทย) ไม่พัง
หายไปเองเมื่อไฟต์จบ ไม่ต้องย้ายข้อมูล

**ชื่อไอเทมที่แอดมินเพิ่มเองผ่าน Panel** — ไม่มีคำแปล → แสดงภาษาไทยตามกฎ fallback

## 5. ไม่แปล

- ข้อความที่แอดมินพิมพ์ใน Panel (ประกาศ · ชื่ออีเวนต์)
- **ชื่อยศดิสคอร์ด** เช่น `"ขอทาน"` — โค้ดใช้เป็นคีย์หายศ (`player_commands.py:271`, `identity.py`)
- ชื่อคำสั่ง `!` และคำสั่งไทยสำรอง (`ซื้อ`)
- docstring · คอมเมนต์ · log ฝั่งแอดมิน · หน้า Panel (`admin.html`)

## 6. ลำดับลงมือ (แต่ละก้อนมีแผนของตัวเอง เทสได้จบในตัว)

| ก้อน | ได้อะไร | เทสได้ว่า |
|---|---|---|
| **1** | `bot/i18n.py` · `i18n.js` · ไฟล์ locales · สคริปต์ดึงข้อความ · ปุ่มเลือกภาษา · แปล**ข้อความในไฟล์ HTML ทุกหน้าผู้เล่น** (รวม `<script>` ในหน้า) + แถบเมนู/ท้ายเว็บใน `web.js` · ไฟล์คำแปลติดไปกับ exe ลูกค้าด้วย | กดเปลี่ยนเป็นญี่ปุ่นแล้วเมนูเว็บเป็นญี่ปุ่น |
| **2** | middleware + ห่อ `tr()` ในแกนเกมที่เว็บเรียก + `HTTPException` + **ข้อความในไฟล์ JS ฝั่งเกม** (`play.js` · `uno.js` · `worms.js` · `scene.js` · `games/**` ฯลฯ รวมที่วาดลง canvas) | ผจญภัยบนเว็บภาษาอังกฤษได้ทั้งเกม |
| **3** | `LangView` + `before_invoke` + `players.lang` + ห่อข้อความบอท | ตั้งดิสคอร์ดเป็นจีน กดปุ่มหนึ่งครั้ง แล้ว `!bag` ตอบจีน |
| **4** | ชื่อในเกม + แยกเก็บชื่อมอน | ชื่อมอน/ไอเทมเปลี่ยนตามภาษาทั้งบอทและเว็บ |

ก้อน 2 กับ 3 ใช้แกนเกมร่วมกัน (`adventure_core` ฯลฯ) — ห่อ `tr()` ครั้งเดียวได้ทั้งสองฝั่ง
ก้อนไหนทำก่อนอีกก้อนก็ได้ผลบางส่วนแล้ว

## 7. ความเสี่ยงที่รู้อยู่

- **ข้อความไทยถูกแก้ทีหลัง** → คีย์เปลี่ยน คำแปลหลุด · กันด้วยเทสในข้อ 1
- **ประโยคที่ต่อจากหลายท่อน** — ต้องรื้อเป็นประโยคเดียวมีตัวแปร ไม่งั้นแปลไม่ได้
- **ความยาวข้อความ** — อังกฤษ/ญี่ปุ่นยาวกว่าไทยในปุ่มเล็ก ๆ (ปุ่มดิสคอร์ดจำกัด 80 ตัวอักษร)
  · ต้องเทสด้วยตาบนมือถือ
- **คุณภาพภาษาจีน/ญี่ปุ่น** — แปลโดย Claude ควรให้เจ้าของภาษาอ่านก่อนโปรโมตกับผู้เล่นต่างชาติ
- **ฟอนต์** — ตรวจว่าฟอนต์เว็บมีอักษรจีน/ญี่ปุ่น ไม่งั้นตกไปใช้ฟอนต์ระบบ (ยังอ่านได้ แต่หน้าตาไม่เข้าชุด)
- **Canvas** (`scene.js` · `worms.js` · ปาร์ตี้) — ข้อความที่วาดลง canvas ต้องผ่าน `t()` ด้วย
  grep ไม่เจอง่ายเท่า HTML

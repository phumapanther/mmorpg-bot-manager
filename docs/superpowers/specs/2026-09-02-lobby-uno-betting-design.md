## สถาปัตยกรรม

### แยกเป็น 2 ชั้น

```
bot/lobby.py  ← ชั้นกลาง ทุกเกมใช้ร่วมกัน
    ห้อง/รหัส · ที่นั่ง · เข้า-ออก · กวาดห้องร้าง
              ↓ เกมเสียบของตัวเองผ่าน extra
    ┌─────────┴─────────┐
 สนามรบ              UNO
 (ทีม/หน้าตาตัว)    (เดิมพัน/บอท)
```

**ชั้นกลางรู้จัก**: `game` · `room_id` · `host` · `seats[]` · `started` · `extra`
**ชั้นกลางไม่รู้จัก**: ทีม · หน้าตาตัวละคร · เงินเดิมพัน (อยู่ใน `extra` ของแต่ละเกม)

### ตารางฐานข้อมูล

```sql
lobby_rooms (room_id TEXT PK, game TEXT, state TEXT, updated_at REAL)
lobby_seats (user_id TEXT, game TEXT, room_id TEXT, updated_at REAL,
             PRIMARY KEY (user_id, game))   -- คนเดียวอยู่ได้เกมละห้อง
```

`PRIMARY KEY (user_id, game)` = เล่น UNO อยู่แล้วเข้าห้องสนามรบพร้อมกันได้
(ของเดิม `worms_seats` มี `user_id` เป็นคีย์เดี่ยว — จำกัดห้องเดียวทั้งระบบ)

### API ชั้นกลาง

| ฟังก์ชัน | ทำอะไร |
|---|---|
| `create(game, uid, seat_data, extra)` | สร้างห้อง คืนรหัส |
| `join(game, uid, code, seat_data)` | เข้าห้อง |
| `leave(game, uid)` | ออก (เรียก hook ของเกมก่อน) |
| `room_of(game, uid)` | อยู่ห้องไหน |
| `load(room_id)` / `save(room_id, st)` | อ่าน/เขียนสถานะ |
| `view(game, uid)` | ส่งขึ้นเบราว์เซอร์ — **ประตูเดียว** |

**hook ที่เกมเสียบได้**: `on_leave` (คืนเงิน/ปรับทีม) · `can_start` (เงื่อนไขเริ่มเกม)

## การไหลของเงิน (UNO)

### กฎเหล็ก

> **ทองรวมในระบบต้องเท่าเดิมเป๊ะทุกกรณี** — เงินย้ายมือ ไม่งอก ไม่หาย

### จังหวะที่เงินขยับ — มีแค่ 2 จุด

| เมื่อไหร่ | ทำอะไร |
|---|---|
| **เข้าโต๊ะ** | หักจากกระเป๋าทันที → เก็บใน `pot` |
| **จบเกม** | จ่าย `pot` ทั้งก้อนให้ที่ 1 |

หักตอนเข้า ไม่ใช่ตอนเริ่ม — กันคนวางเงินแล้วไม่มีจ่าย
(แบบเดียวกับ `blackjack_core.start()`)

### 4 กรณีที่ต้องคุม

| กรณี | ผลลัพธ์ |
|---|---|
| ออกกลางเกม | เงินตกกองกลาง คนที่เหลือเล่นต่อ ที่ 1 กินหมด |
| เน็ตหลุด | ไม่เตะทันที บอทเล่นแทน กลับมาต่อได้ |
| ยุบโต๊ะก่อนเริ่ม | **คืนเงินทุกคนเต็มจำนวน** |
| เหลือคนเดียว | คนนั้นได้ `pot` (ทุนตัวเอง + ของคนหนี) |

### กันฟอกทอง

```
โต๊ะเดิมพัน = คนจริง 2 คนขึ้นไปเท่านั้น
มีบอทในโต๊ะ → เดิมพันเป็น 0 อัตโนมัติ
```

เปิด 2 ดิสหลอกเล่นเอง = ย้ายเงินจากบัญชีตัวเองไปอีกบัญชี **ยอดรวมไม่เพิ่ม**

## หน้าจอ

### ตำแหน่งปุ่ม

```
🧭 ออกผจญภัย
   🎪 ล็อบบี้ · ชวนเพื่อนเล่น   ← ใหม่ บนสุด
   🧭 เริ่มออกเดินทาง             ← เดิม
   ⏩ เดินเร็ว ×5                 ← เดิม

⚔️ PVP
   🎯 สนามรบผลัดเทิร์น           ← เดิม ไม่แตะ

🎰 คาสิโน
   🃏 ศึกไพ่รูน                   ← เดิม (ข้างในเพิ่มหน้าเลือกโหมด)
```

**2 ทางเข้า ปลายทางเดียวกัน** — คนที่ชินปุ่มเดิมไม่ต้องเปลี่ยนพฤติกรรม

### การไหลของหน้า

```
🃏 ศึกไพ่รูน (ปุ่มเดิม)
      ↓
 หน้าเลือกโหมด (ใหม่)
   🤖 เล่นกับบอท    → เข้าเกมเลย (ของเดิม)
   👥 เล่นกับเพื่อน  → ล็อบบี้
```

**ในโต๊ะก่อนเริ่ม**: คนที่นั่งอยู่ · รหัสกดคัดลอก · รายชื่อเพื่อน+ปุ่มชวน · เจ้าของโต๊ะเริ่มได้เมื่อครบ 2 คน

### คำเชิญผ่าน DM

```
🃏 [ชื่อคุณ] ชวนคุณเล่นอูโน่เดิมพัน!
💰 เดิมพัน 1,000 ทอง · รหัสห้อง A7K2
[✅ เข้าร่วม]  [❌ ไม่เล่น]
```

ใช้แบบแผนจาก `guild.py:53` (GuildInviteView) — ชวนได้เฉพาะเพื่อนจริง (`are_friends`)
เพื่อนปิด DM = บอกให้ส่งรหัสเอง

## แผนย้ายสนามรบแบบไม่พัง

**ส่วนที่เสี่ยงที่สุดของงานนี้** — สนามรบยังไม่ได้เทสกับคนจริง (ต้องรอ 2 คน)

| ขั้น | ทำอะไร | กันพังยังไง |
|---|---|---|
| 1 | สร้าง `lobby.py` + เทสครบ | ยังไม่แตะสนามรบ |
| 2 | `rooms.py` → เปลือกบางเรียก `lobby.py` | **ชื่อฟังก์ชันเดิมทุกตัว** |
| 3 | รันเทสสนามรบทั้งหมด | ผ่านเท่าเดิมเป๊ะ ไม่งั้นถอย |
| 4 | UNO ใช้ `lobby.py` | ของใหม่ |

**กุญแจ**: `rooms.py` ต้องเก็บชื่อเดิมไว้**ครบทุกตัว** — นับจากโค้ดจริงที่เรียกอยู่:

| ใครเรียก | ฟังก์ชัน/ค่าคงที่ห้ามเปลี่ยนชื่อ |
|---|---|
| `match.py` | `load` `save` `leave` `room_of` `plan_ready` `TEAM_NAME` `TEAM_PLANS` |
| `web_api.py` | `create` `join` `leave` `set_plan` `set_team` `view` |

รวม public ทั้งหมด  11 ตัว: `new_code` `room_of` `load` `save` `create` `join` `leave`
`set_plan` `set_team` `plan_ready` `view` + ค่าคงที่ `MAX_SEATS` `ROOM_TTL` `TEAM_NAME` `TEAM_PLANS`

เก็บชื่อเดิมครบ = `match.py` กับ `web_api.py` **ไม่ต้องแก้สักบรรทัด**

⚠️ `set_plan` / `set_team` / `plan_ready` เป็นเรื่องทีม**เฉพาะสนามรบ** — ไม่ขึ้นชั้นกลาง
อยู่ใน `rooms.py` ต่อไป ทำงานกับ `extra` ของห้อง

**ข้อมูลเก่า**: ห้องใน `worms_rooms` อ่านต่อได้ช่วงเปลี่ยนผ่าน (ห้องมีอายุ 3 ชม.อยู่แล้ว)

## ความปลอดภัย

### ไพ่ห้ามหลุด (กติกาเหล็กจากแผนเดิม)

`view(uid)` เป็นประตูเดียวก่อนส่งขึ้นเบราว์เซอร์ — **ซ่อนด้วย CSS ไม่นับว่าซ่อน**

| ส่งได้ | ห้ามส่งเด็ดขาด |
|---|---|
| ไพ่ในมือ**ตัวเอง** | ไพ่ในมือคนอื่น (แม้ใบเดียว) |
| คนอื่นเหลือกี่ใบ | ลำดับไพ่ในกองจั่ว |
| ไพ่บนสุด + สีปัจจุบัน | ไพ่ในมือบอท |

เทส 2 ชั้นแบบ `test_worms_props.py` (คุมที่ฟังก์ชัน + คุมที่คำตอบ HTTP จริง)

### จุดอื่น

| ความเสี่ยง | วิธีกัน |
|---|---|
| สั่งแทนคนอื่น | เช็คว่าคนส่งคำสั่งเป็นเจ้าของตาจริง |
| สแปมชวน | จำกัดความถี่ต่อคน |
| ชวนคนไม่ใช่เพื่อน | เช็ค `are_friends` ฝั่งเซิร์ฟเวอร์ |
| กรอกรหัสมั่ว | รหัสหมดอายุ + กวาดห้องร้าง |
| จ่ายรางวัลซ้ำ | จ่ายได้ครั้งเดียว (เน็ตกระตุกยิงซ้ำ) |

## เทสที่ต้องมี

### ล็อบบี้กลาง
- สร้าง/เข้า/ออกห้อง · รหัสไม่ซ้ำ · ห้องเต็มเข้าไม่ได้
- คนเดียวอยู่ได้เกมละห้อง (UNO + สนามรบพร้อมกันได้)
- เจ้าของออก → โอนสิทธิ์ให้คนถัดไป
- ห้องร้างถูกกวาดทิ้ง

### เงิน (สำคัญสุด)
- **ทองรวมก่อน = หลัง** ทุกกรณีรวมออกกลางคัน
- เล่น 100 ตารวด ทองรวมนิ่งสนิท
- มีบอทในโต๊ะ → เดิมพันเป็น 0 เสมอ
- เงินไม่พอเข้าโต๊ะไม่ได้ ไม่ติดลบ
- กดจ่ายรางวัลซ้ำ → จ่ายครั้งเดียว

### ย้ายสนามรบ
- เทสสนามรบเดิมทั้งหมดผ่านเท่าเดิม (เกณฑ์ตัดสินว่าย้ายสำเร็จ)

### ความลับ
- ไพ่คนอื่นไม่หลุดจาก `view()` และไม่หลุดจาก HTTP จริง

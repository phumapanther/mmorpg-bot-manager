# 🌐 หน้าเว็บเกม — ไฟล์ static

รื้อโครงสร้าง 2026-09-02 (ขั้นที่ 5, ขั้นสุดท้าย) — ผ่า `play.js`
(เดิม 4,265 บรรทัด 175 ฟังก์ชันไฟล์เดียว) เอาหมวดสนามรบ Worms ออกมาแยกไฟล์
(เว็บยังโหลด/เล่นเหมือนเดิมเป๊ะ — แค่ย้ายโค้ดให้ชัดว่าใครดูแลไฟล์ไหน
**ไม่มีการเปลี่ยนพฤติกรรมแม้แต่บรรทัดเดียว**)

```
license_server/web_static/
├── play.js            เมนู · โปรไฟล์/สไปรต์ · ธนาคาร/ทองคำแท่ง · ร้านค้า/ตลาด/คราฟ
│                       · แฟชั่น/กาชา · เพื่อน/คู่หู · คาสิโน (ไฮโล/แบล็คแจ็ค/สล็อต)
│                       · บอร์ดรางวัล · ฉากผจญภัย (2,304 บรรทัด)
├── games/
│   └── worms_ui.js    ฟังก์ชัน wm* ทั้ง 90 ตัว + fillWorms + ตัวแปร global
│                       ของหมวดสนามรบ Worms (1,889 บรรทัด)
├── worms.js            เอนจินสนามรบ (วาดแผนที่ + กล้อง) — คนละไฟล์กับ worms_ui.js
├── scene.js / sprite.js / walk.js   เอนจินฉากผจญภัย/สไปรต์/การเดิน
├── sfx.js / web.js     เสียง / ตัวช่วยกลางร่วมทั้งเว็บ (esc, api, toast ฯลฯ)
└── uno.js              เกม UNO แยกเป็นเอกเทศอยู่แล้วตั้งแต่แรก
```

`play.html` โหลดตามลำดับ: `web.js → sfx.js → worms.js → walk.js → sprite.js
→ scene.js → play.js → games/worms_ui.js → uno.js`

## กฎการแบ่งงาน

- **`games/worms_ui.js` ต้องโหลดหลัง `play.js` เสมอ** — ฟังก์ชัน wm* เรียก
  ตัวช่วยกลาง 4 ตัวจาก `play.js`: `bindInviteButtons` · `inviteFriendsHtml`
  · `reload` · `toast` ถ้าสลับลำดับจะได้ `ReferenceError` ตอนโหลดหน้าเว็บจริง
  (เทสจับไว้ที่ `tests/test_web_split.py`)
- ฟังก์ชันใหม่ในหมวดสนามรบ **ตั้งชื่อขึ้นต้นด้วย `wm`** แล้วจะอยู่ฝั่ง
  `games/worms_ui.js` โดยอัตโนมัติเวลาเช็คด้วยเทส (ยกเว้น `fillWorms` ที่ไม่ได้
  ขึ้นต้น `wm` แต่ก็อยู่ไฟล์นี้ — เป็นจุดเข้าตอนกดเปิดสนามรบ)
- ไฟล์พวกนี้เป็น **script ธรรมดาโหลดผ่าน `<script src>`** ไม่ใช่ ES module
  **ห้ามใส่ `import`/`export`** เด็ดขาด (คุมด้วยเทส) — ตัวแปร/ฟังก์ชัน top-level
  ทุกตัวใช้ร่วมกันข้ามไฟล์ผ่าน scope กลางของเบราว์เซอร์ (ไม่ใช่ module scope)
- เทสที่เคยอ่าน `play.js` ไฟล์เดียวแล้วค้นข้อความ (เช่น `"function wmXxx(" in PLAY`)
  ให้เปลี่ยนมาเรียก `tests.conftest.play_js_source()` แทน (รวม `play.js` +
  `games/worms_ui.js` + `shop_ui.js` ถ้ามีไฟล์นั้นแล้ว) — เทส JS (`node tests/*.js`
  ที่ `grab()` ฟังก์ชันด้วยการค้นข้อความ) ใช้ `tests/_js_source.js::playSource()`
  คู่กัน **ลำดับต่อกัน: `play.js` มาก่อนเสมอ แล้วตามด้วย `games/worms_ui.js`**
  — เทสที่ slice ช่วงข้อความแบบ "จาก X ถึง Y" ต้องมั่นใจว่า Y อยู่หลัง X จริง
  ในลำดับนี้ (ดูกับดักข้อ 3 ด้านล่าง)

## ⚠️ กับดักที่เจอจริงตอนรื้อ (09-02) — อ่านก่อนแก้ไฟล์ในนี้

**1. `play.js` ไม่มี `import`/`export` เหมือนไพทอน — ทำสะพานแบบขั้นก่อน ๆ ไม่ได้**

ขั้นรื้อ Python (`web_api.py`) ใช้สะพาน `from ... import *` ได้เลย แต่ JS แบบนี้
เป็น script ธรรมดา ต้องพึ่งลำดับ `<script>` ในหน้า HTML แทน ฟังก์ชัน/ตัวแปร
`let`/`const`/`function` ระดับบนสุดของทุกไฟล์ที่โหลดมาแชร์ scope เดียวกันเอง
โดยอัตโนมัติ — **ไม่ต้อง (และห้าม) export ข้ามไฟล์**

**2. ตัวแปร global ต้องย้ายไปพร้อมฟังก์ชัน ไม่งั้น `ReferenceError` ที่เทสข้อความจับไม่ได้**

`play.js` เดิมมีตัวแปร `WM`/`WM_*`/`wmLoop`/`wmTimingOut` เกือบ 60 ตัวประกาศ
กระจายอยู่ทั่วไฟล์ (ไม่ใช่ก้อนเดียว) บางบรรทัดประกาศหลายตัวพร้อมกัน เช่น
`let WM = null, WM_CAM = null, WM_ST = null;` — เทสอ่านข้อความอย่างเดียวจะ
มองไม่เห็นปัญหานี้เลยเพราะโค้ดยัง "มีอยู่" แค่คนละไฟล์กับฟังก์ชันที่ใช้มัน
ต้องมีเทส **โหลดไฟล์จริงเข้า `vm` แล้ววาดเฟรมจริง** (`tests/worms_boot.js`)
ถึงจะจับได้ — ล้อกับ `tests/uno_boot.js` ที่มีอยู่แล้ว

**3. เทสที่ slice ข้อความ "จาก X ถึง Y" พังเงียบถ้า Y ย้ายไปอยู่คนละไฟล์**

สอง unit test (`test_worms_map.py::_worms_js`, `test_worms_move.py`) เคยตัด
"ทั้งหมวดสนามรบ" ด้วย `PLAY[PLAY.index("let WM = ..."):PLAY.index("let FRIENDS = null;")]`
— ใช้ได้ตอน `play.js` เป็นไฟล์เดียว เพราะหมวดเพื่อนอยู่ "ถัดจาก" หมวดสนามรบพอดี
พอย้ายหมวดสนามรบไป `games/worms_ui.js` (ต่อท้ายในซอร์สรวม) จุดเริ่ม (`let WM = ...`)
ย้ายไปอยู่ **หลัง** จุดจบเดิม (`let FRIENDS = null;` ยังอยู่ `play.js`) เลย
`PLAY.index(Y, a)` หา Y ไม่เจอ (เพราะ Y อยู่ก่อน a ในสตริงรวมแล้ว) → `ValueError`
แก้โดยตัดถึงท้ายสตริงแทน (`PLAY[a:]`) เพราะหลังผ่าไฟล์ หมวดสนามรบทั้งหมดอยู่
ท้ายซอร์สรวมพอดี (เป็นไฟล์เดียวที่ต่อท้ายสุด ไม่มีอะไรแทรกกลาง)

**4. โค้ด top-level (ไม่ใช่ function/let/const) ก็ต้องตามไปด้วยถ้าอ้างของที่ย้าย**

นอกจาก 90 ฟังก์ชัน `wm*` แล้ว ยังมีโค้ดผูกปุ่ม/คีย์บอร์ดที่รันทันทีตอนโหลด
หน้าเว็บ (ไม่ได้ห่อในฟังก์ชัน) เช่น
`document.querySelectorAll('[data-wm]').forEach(...)` ที่อ่านตัวแปร `WM_ACT`
**ทันทีตอนโหลด** (ไม่ใช่ตอนคลิก) — ถ้าย้ายแค่ฟังก์ชันแต่ลืมย้ายบล็อกนี้ไปด้วย
`WM_ACT` จะยังไม่ถูกประกาศตอนบรรทัดนี้รันถ้าลำดับ `<script>` ผิด
เจอเพิ่มอีกจุด: `addEventListener('resize', () => wmFitCanvas())` ไม่มี
`document.`/`window.` นำหน้า ทำให้ค้นด้วย `grep "^document\."` มองไม่เห็น
ต้องไล่หา top-level statement ทุกแบบ ไม่ใช่แค่ที่ขึ้นต้นด้วยคำที่คุ้นเคย

**5. เทส 36 ไฟล์ (ไพทอน) + 6 ไฟล์ (Node) อ่าน `play.js` ตรง ๆ**

แก้ด้วยสูตรเดียวกับขั้นที่ 4: `tests/conftest.py::play_js_source()` (ไพทอน)
+ `tests/_js_source.js::playSource()` (Node) — ทำเป็นก้อนแรกก่อนย้ายโค้ด
แม้แต่บรรทัดเดียว เทสยังเขียวเพราะตอนนั้น helper ยังอ่าน `play.js` ไฟล์เดียว

**6. `shop_ui.js` (ร้านค้า/ตลาด/กาชา/คาสิโน) — ข้ามในรอบนี้**

พันกับตัวแปรกลางของทั้งหน้า (`CHAR`, `LAST`, `showPanel`, ปุ่ม `data-go`)
มากกว่าหมวดสนามรบเยอะ และไม่มีการสำรวจ call-graph มาก่อนแบบหมวดสนามรบ
(ที่รู้แน่ชัดว่าเรียกออกนอกกลุ่มแค่ 5 ฟังก์ชัน) ความเสี่ยงสูงกว่าความคุ้มค่า
ในรอบนี้ — ยังอยู่ใน `play.js` ตามเดิม
